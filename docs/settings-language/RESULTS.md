# 实验结果与变化审阅

结论：在这次 Settings 的范围内，**真实实现＋组合插槽＋明确的变化记录＋渲染与行为检查**已经形成可工作的闭环。新增的连接行可以承载另一种导出流程；原来的 Settings 展示没有因此被重画。

这不等于证明 AI 能稳定处理所有设计需求，也没有测量人的审阅时间。当前可交付的是一个可继续使用、可检查、可扩展的工作方式及其首轮实现。

## 对照发现

同一份长文案任务在 390px 下，Notifications 选择长德文选项后，直接组合现有接口产生 **145px 横向溢出**；继承式扩展为 **0px**。另外三个场景在这项指标上两种实现都为 0。

这说明已有组件并不普遍失效，也说明“没有横向滚动”不能单独代表设计品质。Integrations 还需要人工观察媒体和文字的关系、操作顺序与详情展开；不能用一个数字替代这些判断。

## 本轮真正改变的地方

| Before | After | Why |
| --- | --- | --- |
| `RowShell` 与 `RowLabel` 私有地写在 rows 中 | 无默认样式改动地提取到共享实现，旧行与新行都引用它们 | 避免复制后逐渐漂移；原版截图验证提取结果 |
| 单行持续左右排列 | 扩展行在内容容器不足 32rem 时让操作排到文字下方 | 给内容与操作明确的空间，不靠截断保住布局 |
| 长描述下媒体垂直居中 | 媒体靠近标题；操作与详情跟随媒体后的文字列 | 保留实体身份与内容的视觉关联 |
| 空的详情槽仍然产生间距 | 没有详情时不渲染该槽 | 移除多余空白，恢复行的节奏 |
| 窄容器继续使用左右 32px 页面边距 | 扩展版在小容器使用 16px，宽容器恢复 32px | 布局改变时连同可用空间一起判断；默认原版不变 |
| 手机里滚动后的文字会经过悬浮导航按钮下面 | 扩展版增加 40px 独立吸顶导航条，内容顶部补偿为 8px，初始标题仍在相同高度 | 给导航保留明确的区域，避免图标与滚动文字混在一起 |
| 长菜单选项会超出视口 | 扩展版弹层受视口约束，选项允许换行 | 完整文字与可点击区域同时保留 |
| 手写抽屉只处理 Escape 与点击遮罩 | Base UI 管理初始焦点、循环焦点、关闭与焦点恢复 | 保存原表面和曲线，同时补完整行为 |
| 进入确认或完成确认时焦点可能丢失，手机上的操作也可能落到可视区域下面 | 打开时聚焦「保持连接」并只滚动 Settings 内部；断开或取消后回到主操作 | 让下一步可见，并让键盘用户可以继续操作 |
| 暗色仅存在于页面内部 | 实验页将主题同步给弹层所在的文档根，离开时恢复 | 菜单不再落回浅色 |

新增 CSS 的尺寸使用已有间距阶梯和 Oreo token。13px/18px/20px 沿用原版行排版；32rem 来自 Tailwind 的 lg 容器尺度，是文字与操作的空间边界。没有从新视觉稿复制另一套颜色、圆角或动效参数。

## 对工作方式的修正

第一版只尝试复用行的外壳；实际预览说明，只保留外壳并不够。窄容器的页边距、媒体的纵向位置、隐藏详情的占位、弹层主题与焦点都会牵动结果。因此变化记录必须描述关系和行为，不能只记录“用了哪些组件”。

验证环境本身也需要检查。早期基线的依赖缓存和字体加载异常造成了错误的截图差异；修正缓存隔离、文件访问路径并要求字体成功加载后，再进行最终比较。不能直接把截图不同都归咎于产品代码，也不能未经定位就更新基准图。

后续可以直接新增一个 recipe 继续使用这套方式。只有当新需求改变了这些结构关系时，才需要扩展底层并重新检查相关原版状态。新设计是否值得成为下一份母版，仍然保留给人的判断。

## 2026-10-13 合入兼容记录

合入 Inbox Stream 时，图标词表新增 `arrow-up-right`、`checks`、`chevron-up`、`hash`，共享动效模块新增 `easeDrawer` 导出；旧图标与动效值保持不变。这四个文件从“原样继承”移入明确记录理由和原始哈希的审阅边界，保护检查仍逐文件执行。目前为 37 个原样继承文件和 13 个审阅边界。上文 41 / 8 为首轮实验数据，后续 label 边界修正增加了第 9 个审阅边界。

新工作区 Vite 冷启动可能超过 5 秒；验证脚本的导航超时独立设为 60 秒，操作等待仍为 5 秒。原版 Settings 对照仍固定在 `f63171f`，没有更新视觉基线或放宽像素容差。

本次最终分项回归：192 组布局、13 项流程检查和 68 张原版对照通过；12 组窄屏展开、导出失败恢复及暗色弹层检查通过。窄屏检查现在先等待字体和确认区滚动完成，再使用原有的 1px 边界断言；失败会保留截图与页面状态。最初整套运行中这一检查发生时序失败，修正测试等待后单独重跑通过，产品源码未因此改变。
