# Animate UI — theme transitions and the property-transition correction

User-requested research, 2026-10-21. Sources inspected: [Theme Toggler](https://animate-ui.com/docs/primitives/animate-ui/theme-toggler) and [Theme Toggler Button](https://animate-ui.com/docs/primitives/animate-ui/theme-toggler-button), current Animate UI documentation. Documentation describes behavior; no claim of a source-code audit or performance benchmark.

The page-level primitive uses the native View Transitions API and a directional snapshot wipe, with a documented 700ms ease-in-out default. Unsupported browsers and reduced-motion preferences switch immediately. Its completion callback commits the theme at the end while `onImmediateChange` can update controls earlier. The button primitive separately animates its icon, so an animated theme icon alone does not demonstrate a whole-page transition.

Historical adaptation (superseded after direct user review): reuse the existing document-level theme owner and tokens, fade the entire page over 220ms with the house ease-out curve. This covers sidebars, component previews, template pages and body portals, without asking every component to duplicate transitions or interpolating layout on every frame. Keep persistence immediate and commit React at the snapshot update; cancel superseded snapshots and ignore stale update callbacks. Skip mount, reduced-motion and unsupported cases; continuous controls remain direct. Do not adopt the longer directional wipe, delayed persistence or an additional component dependency.

Implementation: `src/lib/theme/transition.ts`, `transition.css`, `store.ts`, `SiteThemeProvider.tsx`. Adoption status: snapshot implementation superseded; delivery and observed coverage are maintained in the existing task [REVIEW.md](/Users/ziye/Documents/Project/Research/output/playground-figma-20261019/REVIEW.md), section “Whole-site Style transitions”, rather than in a second audit index. The crossfade visually bridges old/new radius and layout; it does not morph each element's geometry independently.


## Correction — interpolate properties, not page screenshots

The user explicitly rejected the page crossfade on 2026-10-21: all changed UI properties must transition. The shared document theme owner now temporarily enables native CSS transitions for the root, descendants and pseudo-elements (including body portals), resolves the before styles, synchronously commits tokens, and resolves the new styles. Color, background, border color/radius/width, shadow, size, padding, margin, gap, type metrics, SVG paint and resulting layout interpolate over 280ms using the existing `--ease-out`. There are no View Transition snapshots, duplicate pages or delayed selections. Presets, mode, radius, density and accent use the same path.

Native CSS retargets from current rendered values during rapid edits. Cleanup is renewed per request, stale cleanup is guarded, and unchanged selections do not cancel a transition. The temporary scope is removed after settlement so ordinary component interaction motion retains its owner. Reduced motion, hidden pages and initial rendering remain immediate. Real layout interpolation and scoped `all` are intentional exceptions to the normal motion guideline, required by this explicit request; replacing these with opacity/scale would reproduce the rejected result.

ASCII artwork remains mounted with interpolated height, margins and opacity instead of toggling display. The hatch uses a registered color value so its paint interpolates without replacing a gradient image. Other non-interpolable discrete properties (notably font-family, content and display) still switch; browser CSS cannot morph between different typefaces. Typography metrics and adjacent layout properties transition wherever interpolable. No claim that unrelated content remounts or arbitrary application layout changes animate.

Validation uses actual computed intermediate values and measured geometry, alongside matched recordings of the real playground. See the same task REVIEW, section “Theme property transitions — correction”. Native CSS behavior references: [Using CSS transitions](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Transitions/Using), [Animatable properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Animations/Animatable_properties). Animate UI remains a research reference; no dependency or snapshot primitive is used.
