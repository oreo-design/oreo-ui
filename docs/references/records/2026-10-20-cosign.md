## 核心结论

静态壳层保持稳定，个性化数据局部补齐；等待期间应减少无意义换形和布局挤动。录屏审查把视觉变化标在时间轴上，帮助发现问题。

## 当时看到了什么

- 审查页的 9.433 秒录屏有 22 条标注。7.100 秒四列骨架、7.433 秒五列人物骨架、8.167 秒内容、8.600 秒补操作并挤动工具栏。
- 刷新到视觉完整 feed 3.28 秒；列表 URL 改变到视觉完整 1.72 秒。这些不是 LCP/INP 或网络瀑布。
- ffmpeg/ffprobe 抽帧与时间戳，Python 找变化候选，Agent/人工判读；模板匹配区分移动与新内容。静态 HTML/JS 用 currentTime、缩略图、归一化矩形与 ResizeObserver 组织审查。
- Oreo CompanyDirectory fixture 保留标题/筛选/侧栏，CompanyTable loading 分支移除表头与排序入口；空、错误与重试展示已查。

## 对 Oreo UI 的参考

- 优先复用稳定壳层，操作立即反映选择，仅加载受影响的内容；初次 loading 与同查询刷新分开。
- CompanyTable 作为共享 owner 保留表结构和排序；骨架与最终几何对齐，晚到图片和操作预留空间。
- PageLoader 的长任务体验、LoadingSequence 的装饰开场和数据骨架不是同一种状态。
- 完整异步模板需覆盖初次进入、筛选、刷新、空结果、失败重试与快速切换；请求排序/取消属于数据层。
- 将可点击时间轴补充进已有任务 REVIEW；可考虑 TimelineTrack / FilmstripPreview / ChangeOverlay，不必先重写媒体分析算法。
