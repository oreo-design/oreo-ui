## 使用与维护

1. 收到新参考先查来源 URL，已有条目则追加带日期的补充，不重复建立竞争记录。
2. 写清原帖实际展示、作者的说法、我们的推断和用户明确认可的内容；技术实现没有源码证据时标为推断。
3. 对 Oreo 的映射指向它自己的组件、tokens、模式和同角色实物，不把竞品风格直接提升为项目规则。
4. 采用或实现后，回填相应 PR、源版本与任务 REVIEW；不删除旧判断，也不把“曾经建议”改写成“当时已做”。
5. 媒体使用相对路径，保留原文件、环境、时间和验证缺口。已有实施任务仍以其 REVIEW 为唯一审查索引。
6. 这是一份研究档案，不是另一本通用 UI 规范；正式规则维护在各自的组件/模式文档及既有审查契约中。

本次可恢复范围是 16 个主题记录、相关历史对话及仓库已有的 75 份审查。它不是账号全部历史聊天的完整导出；未找回的项目不要标成“从未分析过”。以后发现遗漏按相同方式补录。
